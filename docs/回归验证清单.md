# 回归验证清单

本文档用于 Day 7 交付前的回归验证。

目标：

- 验证 Docker 部署链路可用
- 验证 MySQL 初始化链路可用
- 验证健康检查符合预期
- 验证 Cookie 登录校验与失败控制符合预期
- 验证关键 API 返回结构符合当前设计

## 1. 回归环境

本轮回归基于以下前提执行：

- 本地系统：macOS
- 部署方式：`docker compose`
- 当前默认配置：`LOGIN_TYPE=cookie`
- 当前未提供真实 Cookie，因此 readiness 预期失败

这不是错误，而是当前设计下的预期行为：

- `liveness` 通过，表示服务活着
- `readiness` 失败，表示业务依赖未完全准备好

## 3. creator 限量抓取回归项

场景 A：creator 模式传 `creator_max_notes_count=0`

检查目标：

- creator 模式保持全量抓取
- 不因为新参数引入兼容性回归

建议检查方式：

- 通过 API 或 CLI 启动一个 creator 任务
- 观察日志中出现 `creator_max_notes_count=0`
- 确认任务会继续翻页，直到平台分页结束

场景 B：creator 模式传 `creator_max_notes_count=3`

检查目标：

- 每个 creator 只抓前 3 条作品
- 详情抓取、存储、评论抓取范围与这 3 条保持一致

建议检查方式：

- 启动 creator 任务时传入 `creator_max_notes_count=3`
- 观察日志中出现 `creator_max_notes_count=3`
- 确认后续只处理 3 条作品，不再继续翻页

场景 C：creator 模式传 `creator_max_notes_count=-1`

检查目标：

- API 请求被参数校验拦截
- 不会启动爬虫子进程

建议检查方式：

- 直接调用 `/api/crawler/start`
- 传入 `creator_max_notes_count=-1`
- 预期返回 `422` 或参数校验错误
